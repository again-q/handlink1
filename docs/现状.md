# 现状（2026-11-12 手 / 2026-11-15 臂 / 2026-11-16 视觉）

一句话：**LG-603 灵巧手已经可以绕过厂商软件，由我们自己发 CAN 帧直接驱动**；**Dobot
Nova 5 协作臂也已经在真机上接通**（网口 TCP/IP，见第 8 节）；**魔方视觉（俯视读 U 面
9 格 + 层转角）已经写成、跑通合成图测试**，但俯视相机还没装、也还没标定（见第 9 节）。

## 1. 硬件链路

```
24V 电源 ── 机械手（左手，CAN ID 0x64 或 0x65，上电后自动识别）
              │
              │ CAN_H / CAN_L
              ▼
        GCAN USBCAN-I  ──USB──  电脑
        （驱动 oem50.inf，设备类型 4，通道 0，1000 kbps）
```

- 断电后手指变软（没有保持力），注意别磕
- **同一时刻只有一个进程能占用适配器**：厂商软件、我们的服务、脚本，三者互斥

## 3. 协议速查（`handlink/screw.py`）

| 帧 | 说明 |
| --- | --- |
| 主机 → 电机 | `[func][nodeId][payload...]`，标准帧，CAN ID = 手部 ID |
| 电机 → 主机 | `[func+1][nodeId][seq][float32 小端 @3]`，7 字节 |
| 心跳 | `[0x05][nodeId][count][calib][running]`，5 字节 |

`func`：`0xA2` 位置 · `0xA4/A6/A8` 读位置/速度/电流 · `0xD0` 电流 · `0xE0` 速度 ·
`0xF2` 使能 · `0xA0` 校准 · `0x0E` 清错 · `0x0A` 复位 · `0xF0` 编码器置零。

心跳里 `calib & 0x08` = 校准成功；`running` 位：`0x01` 运行、`0x10` 电流限幅、
`0x20` 位置限幅、`0x02/0x04` 硬件/软件过流、`0x08` 电压异常。

**float 是小端**——这是最容易搞错的地方，厂商源码里显式写了 `LITTLE_ENDIAN`。

## 6. 已知的坑

1. **必须常开收包线程**。手每秒灌 3000 帧，不收就会把驱动接收缓冲填满，
   之后 `Transmit` 直接阻塞。`canbus.Hand` 已经处理好了。
2. **电流太低会卡**。0.6 A 时多指同动触发 I-LIM，停在 118°；1.0 A 稳定。
3. **拇指电流上限 0.8 A**，`poses.py` 会自动按关节钳位。
4. **适配器独占**。`OpenDevice => 0` 就是有人占着，先停服务/关厂商软件，再不行拔插 USB。
5. **`skills.MAX_TORQUE = 0.5` 与真机不符**（待改 1.0），速度 `MAX_SPEED = 120` 也偏慢（建议 200）。
   不改的话，走 AI 那条路点"握拳"会卡在半途。
6. **厂商 `LG-603.exe` 要管理员权限**，且按相对路径加载 DLL，必须在 `pkg\LG-603` 目录里启动
   （仓库根的 `启动LG603.bat` 已处理）。我们现在不需要它。
7. `.tmp/` 里有几个 0700 空目录删不掉（沙箱权限），0 MB，无影响。

## 8. 协作臂（2026-11-15 实测接通）

臂跟手不是一条链路：手走 CAN，臂走网口。这次是把臂单独接进来验证的，手当时没插。

### 8.1 链路

```
PC ──USB 网卡「以太网 2」（静态 192.168.5.100/24）── 网线 ── DSC 控制柜 192.168.5.1
                                                              │
                                                        29999 控制 / 30004 反馈 / 502 Modbus
```

接上后**必须自己配静态 IP**：控制柜不发 DHCP，网卡会停在 `169.254.x`，看起来「连着」但
什么都 ping 不到。之前 `docs/NV050-1-对接方案.md` 8.4 写了这一步，实测确认是必需的。

### 8.2 上电初态（踩到的第一个坑）

控制模式不是 TCP，**所有** Dashboard 指令都回 `Control Mode Is Not Tcp`——包括只读的
`GetPose()`。也就是说控制模式没切之前，一条信息都读不到。

手册 2.1：只有「未上电（3）」或「下使能（4，且非暂停、非松抱闸）」才允许切。
本次实测到的初态正好是 4，符合条件。

### 8.3 实测数字

| 项目 | 值 |
| --- | --- |
| 初态 | `RobotMode=4`（下使能），无报警，抱闸全松，母线 48.2 V |
| `RequestControl()` | 一次成功，之后 `GetPose()` 正常 |
| 使能 | `EnableRobot()` 后 `RobotMode=5`（使能空闲） |
| 使能前后位置变化 | **0.02 mm**（说明之前不是靠外力托着，可以直接使能） |
| 反馈口 | 30004，约 125 帧/秒（手册标称 8 ms），0 错帧 |
| 速度因子 | 已设 20%（首次上线按安全红线来） |
| 运动 | `MovJ(joint=…)` 让 J1 ±3°：0.6 s 到位，来回各一次，**回到原点偏差 0.00 mm** |
| 收工 | `Stop()` → `DisableRobot()`，之后 10 s 内位姿漂移 <0.05 mm，无报警 |

### 8.4 反馈协议和仓库原来的假设不一致

原来没有代码碰 30004。按《TCP/IP-API-V4.6.0》123~126 页写的 `handlink/arm_feed.py`：

- 固定 **1440 字节/包**，头 2 字节是包长，末尾 `SafetyState` 的位是**低有效**；
- 所有数值都是**小端**（和 CR 系列那种大端 double 数组的写法不同）；
- 第 48~55 字节是`TestValue = 0x0123456789ABCDEF`，用来确认没接在半包上；
- `QActual` 在 432、`ToolVectorActual` 在 624、`EnableStatus` 在 1026。

`tests/test_arm_feed.py` 用合成包把这些偏移和字节序钉死了，换固件时先看它炸不炸。

### 8.5 三个脚本（上线 / 试动 / 收工）

```bash
python scripts/arm_up.py                    # 只读
python scripts/arm_up.py --yes --speed 20   # 接管 → 设速 → 使能，每步用反馈复核
python scripts/arm_nudge.py --joint 1 --delta 3        # 试动：只打印计划
python scripts/arm_nudge.py --joint 1 --delta 3 --yes  # J1 转 3° 再原路回位
python scripts/arm_down.py --yes            # 收工：Stop() + DisableRobot()
```

`arm_up.py` 先判 `RobotMode` 是不是 3 或 4，不是就直接拒绝发 `RequestControl()`，不硬试。
`arm_nudge.py` 用 30004 判到位（连续 3 帧都在 0.3° 内），超时就 `Stop()`，不管成败都回原位；
单次行程超过 10° 直接拒绝，第一次试动只允许小角度。

### 8.6 还没做的

- 手没接，所以「臂带手抓东西」整条链路还没在硬件上跑过；
- 运动只验证了**单关节 3°**：笛卡尔 `MovL`、多轴联动、连续轨迹都没试；
- `arm.py` 的 `MovJ(pose=…)`（笛卡尔目标）没在真机上试过，只有 `MovJ(joint=…)` 验证过；
- 30005/30006 端口（200 ms / 可配置反馈）没试；
- 急停、防护性停止这些安全位现在只是在反馈里读得到，没有接进服务逻辑；
- `brakes` 字段实测恒为 0（使能、下使能都是），手册的 `BrakeStatus` 表还没对清楚，
  所以脚本只把它打印出来，不敢拿它判断「抱闸到底抱没抱」。

### 8.7 三维视图（`/arm3d`）—— 2026-11-17 换成原厂 STL + 安全环境

**为什么换**：胶囊 + 关节球的版本只能看个大概，做不了安全环境——连杆粗细、手腕
在哪、离桌子多远都是猜的。现在直接用厂家几何：

* **模型**：`handlink/static/nova/` 下 7 段原厂 STL（base_link + Link1~Link6，来自
  `nova5_2f85_description`，和 `kin.py` 的关节原点同源），按 URDF 帧挂到正解位姿上；
  配色按手册封面（白色壳体 + 蓝色大臂/肩罩/底环）。末端是 LG-603 灵巧手
  （掌、四指三节、拇指、法兰；弯曲量取 `/state`）。
* **工位**：`handlink/cell.py` 定义桌面、料盒、相机立柱、防护栏、操作员（8 段胶囊）、
  禁入柱；页面画的和 `/arm/check` 算的是同一份。
* **碰撞代理**：`scripts/build_nova_assets.py` 沿每段 STL 的长轴切片 → 71 段胶囊
  （`static/nova/proxies.json`，P90 径向、外扩 2%）。页面 8 Hz 算最小间距：
  到障碍/人/桌面/地面，以及自身隔两段以上的连杆。
* **安全闸门**：`POST /arm/check` 按 2° 采样扫整条 MovJ 路径；`apply=true` 时服务端
  再扫一遍，低于 60 mm 直接拒绝。SSM 用 ISO/TS 15066 简化式 `v·t + v²/(2a) + C`，
  参数是工程假设值（`cell.ssm_required`）。
* **正解没变**：还是 2026-11-15 真机那组角/位姿，位置差 1.6 mm、姿态差 0.1°
  （`tests/test_kin.py`）；新增的 `tests/test_cell.py` 钉住胶囊距离、工位间距、
  路径校验和 SSM。
* **数据源/下发**：真机在线跟 30004（每 100 ms），不在线退回滑块；下发仍要求
  在线 + 已使能 + 无报警 + 未运动。页面上的「机械臂使能」卡片（`POST /arm/enable`）
  走 29999：需要时先 `RequestControl()`，设速度因子（默认 20%），再
  `EnableRobot()` / `DisableRobot()`，最后用 30004 的 `EnableStatus` 复核。

> 试过的另一条路：`pkg/dobot/DOBOT-Nova5-20221011.stp`（18.5 MB 整机 STEP）能用
> cascadio 转成 GLB（23 万三角面、5.3 MB），但装配层级是零件号、姿态也不是零位，
> 要拆成关节链得先解出每个 joint 的轴，成本比用 URDF 的 Link STL 高得多。
> URDF 那套本身就是厂家几何、还自带 Link 帧，所以选它。

### 8.8 相机实时环境（2026-11-17）

## 9. 魔方视觉（2026-11-16，软件就绪）

**做什么**：俯视相机看一眼托盘里的魔方，回答「朝上那面 9 格各是什么颜色」和
「这一层相对托盘转了多少度」。这是《魔方单手方案》里的 M2/W3。

### 9.1 怎么用

    python -m handlink serve --bus sim      # 只调视觉可以不带手
    # http://127.0.0.1:8766/vision

网页上三步：开相机 → 复原魔方六面各学一次颜色 → 摆正后「设托盘基准」。
详细说明见 docs/视觉接入.md。

    python scripts/vision_check.py --self-test        # 合成图自检，不接硬件
    python scripts/vision_check.py --open 0 --backend dshow
    python scripts/vision_check.py --image shot.png

### 9.2 实测（合成图）

| 项目 | 数值 |
| --- | --- |
| 单次识别 | 中位 130 ms、p90 175 ms（640×480，面约 170 px；干扰物越多越慢） |
| 角度误差 | < 2.5°（0/8/20/33/45/60/72/−25° 都测过） |
| 90° 整转 | 9 格颜色正确换位（本体朝向取样） |
| 全白面 | 靠黑色骨架兜底能认出来 |
| 背景 | 空白桌面/白纸不会被当成魔方 |
| 测试 | tests/test_cubecv.py 10 个，全部合成图，4 s 跑完 |

### 9.3 关键设计

- **不训练模型**：彩色贴纸的 minAreaRect 给格子边长和朝向 → 3×3 点阵反推面中心 →
  用「内部格线够黑 + 颜色落在调色板附近」给候选打分，最高分的那个就是 U 面。
- **一块贴纸 vs 九块糊成一块**：同一块色斑按 单块（÷0.92）/ 两连（÷1.84）/ 整面
  （÷2.88）三种解释都试一遍，让打分去否定错的那个。
- **9 格按本体朝向取**（不是跟着层转）：层转 90° 后颜色会整体换位，这才是状态。
  层转到 45° 附近格子压在缝上，reliable=false，只信角度。
- 标定存 config/vision.json（调色板 6 个 Lab 参考 + 基准角 + 手动四角）。

### 9.4 还没做

- **相机没装**：本机只有那台对着天花板的 USB Camera，俯视用的
  USB2.0 PC CAMERA 和 Gemini 336L 现在是拔掉的。
- **相机后端有坑**：同一台机器上 msmf #0 有时打得开但 0 fps，换 dshow #0 正常。
- **没标定过真机**：调色板、基准都是空。
- **没手眼标定**：像素坐标还没映射到臂基座。
- **只读一面**：底面看不见，侧面要靠骨架外框另做。

### 9.5 只要位置：`boxcv`（2026-11-19）

抓取不需要 9 格颜色时，走 `handlink/boxcv.py`：高饱和、非蓝桌面的色块 →
最大连通块 → **底边接触点**（z=0，没有高度视差）反投影 → 沿画面「上方」走
半个边长 → 立方体底面中心。

- `/scene/detect` 在 `cubecv` 读不出面时自动退回这条，写进同一张物体表
  （`相机·魔方`，TTL 3 s）；后台 `VisionHub` 也一样。
- 09:01 的实拍帧算得 **(375.6, −638.0) mm**，与 11-18 晚的 (376.1, −638.9) 差
  < 2 mm；检测耗时 7–20 ms（640×480，魔方约 110×100 px）。
- 只要求「是个立方体」：图案贴纸、斜视、顶面过曝都能框；代价是没有面状态。
- 相机或桌面动过之后，旧的单应就失效，基座坐标必须重标；像素框不受影响。
  测试 `tests/test_boxcv.py` 10 个。

## 11. 数据手套（2026-11-19 并入；2026-11-20 两次修：手臂转动 / 拇指外展）

以前是 `tools/glove_bridge.py` 单独跑、每帧再 POST 一次 `/pose`；现在收帧和换算
都在 `handlink/glove.py`，服务自己就是一个手套接收器，插件页面直接开关。

```
手套 → MotionVenus → UDP 127.0.0.1:5001 → glove.py → App.apply() → CAN / 仿真
```

- **帧**：一帧拆成 `subpackage 1/2`、`2/2`，按 `fn` 合并后 32 关节 × 6 数
  `[x,y,z,ex,ey,ez]`；右手 0~15、左手 16~31。拼不上的半帧留最近 8 个 fn，
  其余直接丢，延迟不累积。
- **换算**：每节用 ZXY 欧拉角拼旋转矩阵，左乘手腕矩阵转置（`R₀ᵀ·Rⱼ`）得相对旋转，
  **再沿该节的屈曲轴投影**（有符号）；六指各自把链上几节加起来，减最近 10 秒最小值
  （摊平基线），乘 `电机上限 / 150° × 增益`。屈曲轴由 `POST /glove/teach` 教出来，存
  `handlink/config/glove_axes.json`；没教的节退回无符号转角。拇指2 上限 45°、其余
  180°，越界先夹住再走 `spec.check`。
- **为什么不再直接用欧拉角**（2026-11-20）：帧里的 `ex/ey/ez` 是**绝对姿态**，手臂一转
  16 个关节一起变，老算法 `max(|ey|,|ez|)` 跟着涨——现场表现就是"手不动、胳膊转一圈、
  大拇指自己动"。拇指最惨：骨头几乎垂直于小臂，滚转在四指那儿进了 roll（`ex`，本来就
  丢），到拇指整个投影到 `ey/ez`；再加 102（三节）和 107（2~3 节）算同一批关节，一份
  干扰算两遍。默认 `frame=rel` 除掉公共旋转，`rel-ext` 是另一种 ZXY 读法，`abs` 留作
  对照（切回去能复现老毛病，`tests/test_glove.py::TestArmRoll` 就钉着这件事）。
- **第二修：拇指外展、还跟着手臂动**（2026-11-20 现场反馈）。`rel` 只消掉"整只手一起
  转"，剩下的量仍是**无符号转角大小**：拇指 CMC 的外展、绕骨头的自转、小臂带动的皮肤
  扭转，全被当成"弯手指"，于是"收拇指"变成"拇指往外展"。两处改：①沿学出来的屈曲轴
  做有符号投影，非屈曲方向投影掉；②拇指拆成 `102←Thumb1`、`107←Thumb2..3`，CMC 一动
  不再同时推两个电机（老映射 `102=(1,2,3)` 与 `107=(2,3)` 重叠）。
- **模板**：`glove.FINGERS` 就是唯一出处，`GET /glove/limits` 的 `chain` 跟着它走。
- **模式**：`glove` 跟手；`code` 手套照收但不发，滑块/点位/动作可以独占手。
- **接口**：`GET /glove/state`，`POST /glove/{start,stop,mode,toggle,zero,gain,frame,
  deadband,teach}`；命令行 `serve --glove [--glove-udp/--glove-side/--glove-gain/
  --glove-frame/--glove-deadband]`。
- **现场量**：`python tools/glove_probe.py --seconds 20`（手指别动、只转手臂），表格里
  合计最小的换算方式就是该用的；`--selftest` 不用手套就能验分析本身。
- **残抖**：`POST /glove/deadband {"deadband":{"102":5,"107":6}}`，别超过 10°。
- **零点改成"粘性地板"**（2026-11-21，为实时任务）：老规则"最近 10 秒最小值"任何一次
  下冲都会立刻变成新零点、接下来 10 秒整只手偏高——任务中的表现是"抓一半手突然合了
  一下"。现在往下要连续低于 0.25 s 才认（单帧毛刺不算），往上贴基线 6 s 后按 2°/s
  慢追（只管温度漂移）。`jumps` 改成 `spikes`：只在"跳上去又弹回"时计数，正常快速
  握拳不算。
- **运行时信号**：`/glove/state` 的 `spikes` / `saturated` / `frame_age_s` + `live`，
  任务里判断"这帧能不能信"就看这三项；`python tools/glove_soak.py --seconds 180`
  边跑任务边记录，结束出掉线/毛刺/饱和/帧率小结 + CSV。
- **摆姿态存点位**：`POST /glove/save {"name":...}` 取最近 5 帧**中位数**存成点位
  （`saturated` 非空说明读数顶上限、点位会被夹）；`POST /point/nudge {"delta":
  {"107":-5}}` 就地改几度并写回点位 + 下发；臂的姿态用 `POST /arm/poses` 存。
  注意这条是"固定某次姿态"，和实时跟手是两条路。
- **插件**：侧栏「机械手」→「数据手套」卡片（启动/停止、左右手、模式、零点、
  增益、六指实时条），服务就绪后按 `gloveAuto` 自动开监听——见
  `handlink-plugin/README.md`。
- **验证**：`tests/test_glove.py` 67 个（解析/分片/零点粘性/增益/限流/模式/绑定失败/
  独占端口/真 UDP 端到端/服务接口/手臂转动解耦/拇指拆分/屈曲轴教学/死区/毛刺）；
  全量离线全绿。真手的手感还要现场戴一次确认——按人调的只剩五样：`--glove-gain`、`frame`、
  教出来的轴、`deadband` 和零点窗口。
- **坑**：5001 同一时刻只能一个程序监听（老的桥接脚本要先关）；手套是逐帧覆盖，
  跟手时按钮指令会被下一帧顶掉。
