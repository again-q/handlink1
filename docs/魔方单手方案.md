# 单手还原魔方：从「有臂有手」到「能解」的实施方案

> 目标：**LG-603 左手 + Nova 5 臂 + 被动托盘**，由这只手把 3×3 魔方还原。
> 定义：手是唯一的操作手；臂负责拿起/放下/换面；托盘只托住最下层；相机和电脑负责看和算。
> 这不是「掌内单手」（那只手做不到），而是「手推层 + 臂换面」，和 FINGR 的做法同源。

---

## 0. 先看结论

| 问题 | 答案 |
| --- | --- |
| 手能不能把一层推 90°？ | **要实测**。这是整个项目的 go/no-go，见 §3。 |
| 怎么换面？ | **不靠手在掌内转**：松开→臂把魔方按目标姿态放回托盘→重新抓。见 §5。 |
| 解魔方难吗？ | 不难（Kociemba 几十毫秒）；难的是**每一次推层/换面/对中**。 |
| 多久能出完整还原？ | 顺利 4–6 周；第一版整场 20–40 分钟，成功率先求 1/1，再谈速度。 |
| 最大的风险？ | 食指单自由度推层会滑/推不够 90°；拇指 0.8 A 夹持偏弱。§9 有备选。 |

## 1. 系统架构

```
              ┌──────────── 相机（俯视托盘）────────────┐
              │  魔方姿态 / 层角度 / 颜色 / 状态        │
              └──────────────────┬─────────────────────┘
                                 │
   PC：状态机 + Kociemba + 规划 ─┼─► 臂（TCP 29999，Nova 5）
                                 │       │
                                 │       └─► 手（CAN，LG-603，1000 kbps）
                                 │
                          托盘（被动，只卡最下层）
```

- 手：`handlink` 已有的 `CanBus`，位置/速度/电流，3000 帧/秒心跳；`poses.py` 的预设是起点。
- 臂：`handlink/arm.py` 的 `DobotArm`（**还没在 Nova 5 真机验证**，第一步先只读 `check()`）。
- 托盘：3D 打印，`docs/cube_tray.scad`，只卡 D 层（19 mm），前后开口给手指。
- 相机：现有 Orbbec Gemini 336L RGB 或 USB 相机，俯视托盘；先不用深度。

## 2. 四个关键决定（建议默认值）

| 决定 | 建议 | 理由 |
| --- | --- | --- |
| 魔方 | **57 mm 竞速魔方**（松、上油、容错好） | 层高 19 mm，和这只手四指间距（约 20 mm）对得上；转动扭矩小 |
| 状态感知 | 先 **颜色 + 初始六面扫描 + 走步推算**；有预算加 **蓝牙智能魔方**（GAN/MoYu）做真值 | 托盘里的底面看不见，纯视觉读不全；智能魔方直接给状态和每一步 |
| 换面 | **臂拿起→转腕→放回托盘→重抓** | 零额外机构；FINGR 的 table-assisted regrasp 同思路；先求通，再考虑转台 |
| 推层 | **食指推 U 层，中指/无名指/拇指夹住中/下层，掌心悬空** | 掌心碰到魔方会把 U 层也压住，推不动；掌心必须离开 |

## 3. M0：推层实验（第一周，go/no-go）

**目的**：回答「食指一次推程能把 U 层转多少度、滑不滑、会不会把层带回去」。

### 3.1 准备

1. 打印托盘（`docs/cube_tray.scad`），夹在桌面固定位置；垫 1.5 mm 硅胶。
2. 手装到臂上，标定法兰→手掌的 TCP；用示教/`GetPose()` 记下托盘上方和抓取位。
3. 魔方放托盘，D 层进槽，U 层朝上。

### 3.2 推层姿势（先按这个试，再微调）

| 手指 | 角度 | 电流 | 作用 |
| --- | --- | --- | --- |
| 拇指1 (102) | 40–55° | 0.8 A（上限） | 压住中/下层对侧 |
| 拇指2 (107) | 25–40° | 0.8 A | 让拇指绕到对侧 |
| 食指 (103) | 起始 0–20° → 推至 110–130° | 0.8–1.5 A | 推 U 层 |
| 中指 (104) | 120–140° | 1.0 A | 夹住 M 层 |
| 无名指 (105) | 130–150° | 1.0 A | 夹住 M/D 层 |
| 小指 (106) | 140° | 0.8 A | 收拢/辅助夹 D |

要点：

- **掌心不要贴到魔方**：靠拇指+中指+无名指把魔方夹在掌外；掌心贴上去会把 U 层也压住。
- 食指的**屈曲轴要和魔方竖轴平行**：手指排竖起来（食指在上、中指/无名指在下），食指指尖沿水平圆弧推 U 层的侧面。
- 拇食指同侧，拇指理想是**绕到对侧夹中/下层**，不要夹住要被推的 U 层，否则和食指打架。
- 先 `speed=40–60`、`current=0.6–1.0`，每次只动食指，手边有人，急停在手边。

### 3.3 跑法

```bash
# 只打印姿态，不动手
python demo/cube_push.py --bus sim --dry-run

# 仿真里跑一遍（确认脚本/录制/分析链路）
python demo/cube_push.py --bus sim --cycles 2

# 真机：第一次务必低电流低速
python demo/cube_push.py --bus can --speed 40 --current 0.6 --index-end 110 --cycles 3
```

每次跑完看 `demo/cube_push-*.jsonl` 的分析：食指行程、峰值电流、电流占用；再用相机/记号量 U 层实际转了多少度。

### 3.4 记录表（每次实验填）

| 项 | 数值 |
| --- | --- |
| 食指一次推程转过的角度 | ___°（目标 90°） |
| 推几次到 90° | ___ 次 |
| 回程有没有把层带回去 | 有 / 无 |
| 魔方有没有被推歪/推出槽 | 有 / 无 |
| 食指峰值电流 / 占用 | ___ A / ___% |
| 拇指峰值电流 / 占用 | ___ A / ___% |
| 20 次重复的成功率（90°±5°） | ___ / 20 |

### 3.5 判定

- **成功率 ≥ 80%**：进 M1（臂抓放/换面）。
- **50–80%**：先调接触点/角度/速度/指垫，再试「拇指+食指捏上层边角」的变体。
- **< 50%**：换路线——先做 **2×2×2**（步数少，FINGR 同款），或试「抓两层转宽层」（接触面积大，但解法要改），或承认这只手只适合做「推一步」的展示。

## 4. 托盘（`docs/cube_tray.scad`）

- 内口 57.7 mm（57 + 0.35×2），深 19 mm，只卡 D 层；左/右两片夹壁，前/后开口。
- 底部 1.5 mm 硅胶垫；夹壁内侧先不加东西，打滑再贴 0.2 mm 防滑胶带（间隙只有 0.35 mm）。
- 4×M4 固定孔；打印 PETG/PLA，4 圈壁厚，30% 填充。
- 换面时臂把魔方拿起、转腕、放回；托盘的方口允许 4 个 90° 摆向，槽口倒角帮助导入。

## 5. 臂的动作：抓 → 转 → 放（换面）

一条最小状态机（先示教 4–6 个位姿，不做通用 IK）：

```
HOME
  → TRAY_ABOVE（托盘上方 100 mm，掌朝下）
  → TRAY_GRASP（下降，手指包住魔方）
  → 手合到 fist（1.0 A，等实际角 ≥ 目标 60%）
  → LIFT（抬起 100 mm）
  → ROT_*（转腕，让目标面朝上；4 个朝向各示教一个）
  → TRAY_ABOVE → TRAY_GRASP → 手张开 → 抬起
  → PUSH_READY（掌竖直、手指排竖、食指对 U 层）
```

- 换面 = 上面这条「抓→转→放」；一次约 15–30 s。
- 抓取用 `poses.POSES["fist"]`，电流 1.0 A；推层用 `point` 变体，食指自由。
- 臂速率先 20%，`move_l` 下探，`move_j` 转腕；每次到位用 `wait_until` 判定。
- 先示教 4 个「目标面朝上」的腕姿；不够再加。**不要一开始写通用 IK**。

## 6. 视觉与状态

> **已落地（2026-11-16）**：俯视读「U 面 9 格颜色 + 层转角」已经写好并跑通合成图
> 测试——网页 /vision、接口 /vision/*、命令行 scripts/vision_check.py、
> 测试 tests/test_cubecv.py。还没在真机上标定，手眼和侧面读数也还没做。
> 详见 docs/视觉接入.md。

### 6.1 最小方案（先做）

- 俯视相机看托盘：读 U/F/R 可见面颜色，测 U 层转过的角度（贴纸边线/网格线）。
- 初始状态：臂把魔方举到相机前，转 3–4 个姿态拍完 6 面；之后靠**走步推算**，每步用可见面校验。
- 底面（D）在托盘里看不见：靠初始状态 + 走步推算；如果推算和可见面冲突，重新扫描/重规划。

### 6.2 更稳的方案（推荐加）

- **蓝牙智能魔方**（GAN 356 i Carry / MoYu WRM AI）：直接给 54 格状态和每一步，省掉最难的感知；相机只负责对中/层角度。
- 或**编码标记**（ArUco/二维码贴纸）+ 多视角重建（FINGR 的做法），但外观不像普通魔方。
- 先用手里的普通魔方跑通，再决定要不要买智能魔方。

### 6.3 标定

- 手眼：相机→托盘、相机→臂基座；用棋盘格/ArUco。
- 托盘：方口中心、槽向、D 层高度；换面后魔方的摆向由臂的腕姿决定，视觉复核。
- 层角度：U 面边线与托盘基准的夹角；容差 ±5°。

## 7. 求解与规划

1. **求解**：`kociemba`（两阶段）；输入 54 格状态，输出 U/R/F/D/L/B 序列。
2. **只做正向 90°**：食指只能往一个方向推，所以把 `X'` 换成 `X3`、`X2` 换成 `X2`。步数会变多（FINGR 的 planner 也是 minimize positive quarter turns）。
3. **按面分组**：连续同一面的转动合并；每组之间插入一次换面（臂抓→转→放）。
4. **换面规划**：当前抓法只能转「朝上的那一面」；把目标面转到朝上，再推。
5. **闭环**：每推一次，相机量角度；不到 90° 就补推；推过头/推歪就重规划；状态不符就重新扫描。
6. **降换面次数**：优先用「同一面的连续转」；如果解序列面变化太频繁，换一个更「面聚簇」的解法（如分层法），或加两轴转台（把换面从 20–30 s 降到 5–8 s）。

> 走步工具已经在 `handlink/cube.py`：解析、取反、按面分组、换面次数/时间估算；
> `tests/test_cube.py` 13 个测试全绿。求解器输出先过它，再交给状态机。

## 9. 风险与备选

| 风险 | 现象 | 备选 |
| --- | --- | --- |
| 食指推层打滑 | 层不转/只转 20–40°/回程带回 | 换硅胶指套、换接触点（侧面靠上缘）、降速增流、换松魔方；改「拇指+食指捏上层边角」 |
| 拇指夹持弱（0.8 A） | 推的时候魔方转/歪 | 中指/无名指加大电流做主夹；拇指只定位；加硅胶拇指套 |
| 只夹住一层困难 | 中指/无名指碰到 U 层 | 手指排更竖/手更靠上；改「抓两层转宽层」（接触面积大，解法要改） |
| 换面对中差 | 放回后歪 2–5°，推层别住 | 托盘倒角+硅胶；视觉复核；放回前微调腕姿 |
| 底面状态看不见 | 状态推算漂移 | 智能魔方；或举起魔方补拍底面；或每几面重新扫描 |
| 整场太慢 | 20–40 分钟 | 两轴转台；减少换面（面聚簇解法）；只演示短打乱 |
| 3×3 推层一直不稳 | M0 不通过 | 先做 2×2×2（FINGR 同款），跑通全流程再回 3×3 |
