# arm3d 界面重构方案

> 目标：不增功能、不减功能，只把现在「12 张卡片一列堆到底」的右侧栏，
> 重组成 **6 个工作域 + 1 个动作台**。三维模型、工位、碰撞、相机、手感全部原样保留。

示意图：

- 重构后的界面 → [`docs/arm3d-redesign-ui.png`](arm3d-redesign-ui.png)
- 现在 / 重构后 信息架构对照 → [`docs/arm3d-redesign-ia.png`](arm3d-redesign-ia.png)
- 可交互的 HTML 草图 → [`docs/arm3d-redesign-mockup.html`](arm3d-redesign-mockup.html)

## 0. 先说清楚：什么不动

这次**只改布局和面板组织**，下面这些一行都不碰（图中底部绿勾那一段）：

| 模块 | 保留内容 |
|---|---|
| 三维场景 | 原厂 Nova 5 STL（`base_link` + `Link1~Link6`）、螺钉线槽关节罩 |
| 工位 | 桌面 1.4×0.9 m、料盒、相机立柱、防护栏、操作员、禁入柱 |
| 碰撞 | 胶囊代理、最小间距、SSM 计算、红点标注最近的一对 |
| 相机 | 桌面单应反投影贴图、视觉物体进碰撞模型 |
| 手势 | 灵巧手五指几何与弯曲联动 |
| 渲染 | three.js 光照 / 阴影 / ACES 色调映射 / OrbitControls |
| 后端 | 所有 `/arm/*`、`/scene/*` 路由与安全闸门 |

改动集中在 `handlink/armview.py` 里的 `HTML` 模板：**CSS + 卡片 DOM + 少量 JS 选择器**。
`parseSTL` / `paintLink` / `buildRobot` / `buildCell` / `evaluate` / `worldCapsules` 等
渲染与几何函数签名与逻辑都不变。

## 1. 现在的三个具体问题

### 1.1 一列到底，画板排第 8 位

右栏现在有 12 张卡片，顺序是：

```
数据源 · 机械臂使能 · 安全状态 · 相机实时环境 · 关节角 · 保存的姿态 ·
组动作 · 二维手绘轨迹 · 末端位姿 · 安全环境 · 灵巧手 · 手腕走线 · 校验后下发
```

最常干的事（画字）在**第 8 张**，得滚动才看得到。而 `/arm3d?panel=trace` 这个入口
现在只能靠 `scrollIntoView` + 闪一下边框来「推到你眼前」——这本身就是布局不合理的补丁。

### 1.2 执行入口散在三处

| 卡片 | 按钮 | 状态文案元素 |
|---|---|---|
| 组动作 | 每个动作一个按钮 | `actMsg` |
| 二维手绘轨迹 | 预览 / 播放 / 下发真机 / 归位 | `padMsg` |
| 校验后下发 | 校验 / 让真机走到这个姿态 / 强制下发 | `sendMsg` |

三张卡片、三套按钮、三个结果元素、三套措辞。而且「归位」放在轨迹卡片里、
「拖动示教」塞在使能卡片里，语义上都不在它该在的位置。

### 1.3 参数没有表

`paper_z`、`tip_offset`、`region_x/y`、`max_step_mm`、`blend_r_mm`、`corner_deg`、
速度、加速度、`safe_mm`、`warn_mm`、`wrist_limit_deg`、`batch_size`……
现在散在各卡片的 `.note` 正文里，用大白话写着，看完也记不住当前值是多少。

## 2. 重构方案

### 2.1 四层结构

```
┌──────────────────────────────────────────────────────────────┐
│ 顶栏   状态 + 全局开关（数据源 / 使能 + 速度 / 间距 / 手腕 / 手型）│  ← 不放动作
├────┬─────────────────────────────────────┬───────────────────┤
│ 左 │                                     │  上下文面板        │
│ 图 │           三维舞台（常驻）            │  只显示当前工作域   │
│ 标 │                                     │  卡片可折叠        │
│ 栏 │                                     │                   │
├────┴─────────────────────────────────────┴───────────────────┤
│ 底部动作台：当前目标 → 4 步流程 → 唯一一组执行按钮 → 结果行      │
└──────────────────────────────────────────────────────────────┘
```

要点：

1. **顶栏**只放「状态」和「全局开关」，**不放任何动作**；
2. **左图标栏**是工作域选择器，**一次只展开一个**，画板默认就是第一个；
3. **右侧面板**只渲染当前域的内容，卡片标题可点，**折叠 / 展开**；
4. **底部动作台**是**唯一**的执行入口，三路动作都汇到这里。

### 2.2 六个工作域

| 域 | 图标 | 内容 | 从哪来 |
|---|---|---|---|
| 轨迹 | 笔 | 画板 + 轨迹参数表 + 方向闭合 + 播放与安全 | 原「二维手绘轨迹」 |
| 姿态 | 旗 | 关节滑块 + 预设 + 拖动示教 + 保存的姿态 + 末端位姿 | 原「关节角」「保存的姿态」「末端位姿」「使能」里的拖动示教 |
| 动作库 | 三横杠 | `arm_actions.py` 里的组动作按钮 | 原「组动作」 |
| 安全 | 盾 | 安全状态 + 手腕走线 + 场景显示开关 | 原「安全状态」「手腕走线」「安全环境」 |
| 视觉 | 眼 | 桌面标定 + 桌上物体 + 叠加开关 | 原「相机实时环境」 |
| 参数 | 齿轮 | 全量参数一张表 | 新增视图，把散落的配置收拢 |

「数据源」「机械臂使能」「灵巧手」这三个不再是卡片，收进顶栏的状态胶囊：

- 数据源 → 顶栏左边的 `仿真 / 真机` 胶囊，点它切换跟随
- 使能 + 速度 → 顶栏中间的使能胶囊（速度输入就嵌在胶囊里）
- 灵巧手 → 顶栏右边 `手 握拳` 胶囊

### 2.3 参数表

每个域里的表**只显示本域相关**的参数，最后一行给出处；「参数」域显示全量。

统一三列：**名称 · 值 · 可改/只读**

| 参数 | 值 | |
|---|---|---|
| 步长 `max_step_mm` | 15.0 mm | 可改 |
| 圆角 `blend_r_mm` | 5.0 mm | 可改 |
| 拐角吸附 `corner_deg` | 50.0° | 可改 |
| 书写速度 | 40 mm/s | 可改 |
| 加速度 `accel_pct` | 0（不设） | 可改 |
| 纸面高度 `paper_z` | 250.0 mm | 只读 |
| 可达区域 x | -320 .. 420 | 只读 |
| 可达区域 y | -480 .. -180 | 只读 |

「可改」的做成行内输入并 `POST` 回服务端；「只读」的浅色显示，并注明出处模块。
表比散文强的点：**当前值是多少，一眼就能看到**，不用去翻 `trace2d.py`。

### 2.4 底部动作台

三路动作（组动作 / 手动姿态 / 二维轨迹）汇入同一套流程：

```
当前目标            1 绘制 ── 2 规划预览 ── 3 播放 / 下发 ── 4 完成
✍ 二维轨迹
38 点 · 15.0 mm    [重新规划] [播放 4×] [安全抬升] [下发真机]
```

- **当前目标**一栏说明这次要动的是谁，来自哪个域；
- **步骤条**统一了「现在到哪一步、下一步能点什么」；
- **四个按钮**的位置固定，含义固定，不再随卡片漂移；
- **结果行**统一成一个：`已规划 38/38 · 失败 0 · 关节跳变 2.84°`，配色语义统一（绿=通过，黄=有警告，红=拦下）；
- 「下发真机」仍然**三重禁用**：真机在线 + 已使能 + 已预览过，且**服务端闸门不变**。

## 3. 合并掉的冗余

| 现在 | 重构后 |
|---|---|
| 5 个「下发 / 执行」按钮散在 3 张卡片 | 1 个动作台，4 步固定流程 |
| 3 套结果文案（`actMsg` / `padMsg` / `sendMsg`） | 1 个结果行 + 统一的颜色语义 |

## 4. 落地方式与风险

### 4.1 改动范围

只动 `handlink/armview.py` 的 `HTML` 字符串：

1. `<style>`：加 `.rail` / `.dock` / `.sec` / `table.p` 等类，`main` 的 grid 从 `1fr 408px` 改成 `66px 1fr 404px`；
2. `<body>`：卡片搬进六个 `<div id="pg1..pg6">`，`<aside>` 里只留一个 `.pbody`；
3. `<script>`：加域切换、折叠、参数表渲染；`main()` 里的绑定改成按新 id 取。

**风险点：现有 JS 用 id 定位元素**（`$("btnSend")` 之类）。搬家时 id 全部保留，
所以 `checkPath()` / `sendToRobot()` / `padPlan()` / `runArmAction()` 这些函数体不用改。
只有「同一 id 出现两次」的地方要小心（下面这条）。

### 4.2 三个需要注意的点

1. **`selHandPose` 现在被两处读**（`padPlan` 和 `padHome`）。搬到顶栏胶囊后要保证只有一份；
2. **`enSpeed` 同理**（`runArmAction` 和 `padSend` 都读它）——它进顶栏后仍是同一个 id；
3. **`cbProxies` / `cbKeepout` / `cbTrail` / `cbCam`** 现在分散，搬进「安全」「视觉」域后，
   初始化函数 `main()` 里的绑定顺序要跟着调，否则首次 `onchange` 拿不到对象。

### 4.3 有一个必须保留的行为

`/trace` 路由是靠对 `HTML` 做字符串替换实现的：

```python
armview.HTML.replace("</head>",
    "<script>history.replaceState(null,'','/arm3d?panel=trace');</script></head>")
```

重构后 `</head>` 还在，所以这段替换照样有效。但 `panel=trace` 的处理要改成
「直接激活轨迹域」，而不是现在的 `scrollIntoView`。

## 5. 验证方式

```bash
python scripts/trace_check.py                              # 49 个单测 + 仿真
python -m unittest tests.test_arm_poses                    # 页面断言
python -m unittest tests.test_trace2d tests.test_trace_apply
```

`tests/test_arm_poses.py::test_page_has_save_button` 会检查页面上仍有
`id="btnSavePose"`、`id="btnForce"`、`保存当前姿态`、`强制下发`。
重构后这四个**都要保留**——按钮可以搬家，但不能消失。

上线后再手工点一遍：

1. 画个圆 → 预览 → 播放 → 状态行对不对；
2. 六个域来回切，卡片折叠状态是否正常；
3. 真机：使能 → 手动摆位 → 校验 → 下发；
4. 切到「参数」域，确认表里的值和 `GET /arm/trace/config` 返回的一致。
