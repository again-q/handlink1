# 毛笔字轨迹模块：平滑下发（2026-11-26 交接）

一句话：**二维手绘轨迹已经能在真机上连续书写，不再「一卡一卡」**。拐角平滑用 `r`
（绝对毫米圆角）而不是 `cp`（百分比），点距从 5 mm 放宽到 15 mm，归位改成「竖直抬起→
平移到起点上方→竖直落下」。

给下一个会话的人看的东西按这个顺序：

1. 现在是什么状态（能做什么、默认参数是什么）
2. 今天踩过的坑（**这几条别再踩**）
3. 还没解决的问题
4. 下一步建议
5. 怎么验证 / 怎么复现数据

## 2. 今天踩过的坑（**别再踩**）

### ① `cp` 在这台固件上基本不做混合

`MovL(pose=...,cp=30)` 控制器**接受**（返回 0），但速度曲线是等幅锯齿——每个点都
减速到 0 再爬起来。这就是「一卡一卡」的真身。

`r`（圆角半径，毫米）才真正生效：同一个位姿，`r=3` 的曲线是连续的一条。

判断依据不要用「总耗时」，要用 `scripts/trace_track.py` 的速度曲线——总耗时里混着
收笔等待，曾被它误导过一次（以为 r 慢一倍，其实那 25 s 里 13 s 是等待）。

### ② `r` 必须是整数

实测：

```
MovL(pose={...},r=3)     → 0,{2}        成功
MovL(pose={...},r=3.0)   → -50001       参数类型错误
MovL(pose={...},cp=30)   → 0,{3}        成功
MovL(pose={...},r=3,a=50)→ 0,{5}        成功
```

`arm.movl_r()` 已经统一取整，用的是 `floor(x+0.5)`——**不要用 `round()`**，Python 的
银行家舍入会把 `2.5` 变成 `2`。

### ③ 圆角半径受几何约束

圆角半径不能超过相邻段长的一半，否则控制器回 `-1`（命令执行失败）。现在服务里自动
压到 `0.45 × max_step_mm`；万一还是被拒，**只让那一个点退回停车走**，不废掉整条笔画，
退回的个数记在 `dispatch.blend_fallback`。

### ④ 腕部预归中：阈值必须卡在限位附近

书写时 J6 会一路累积旋转（一条 300 mm 的线约 50°）。不干预就会顶到限位——实测
`J6=-357.9°` 时整台臂报警。

但「绕回等价角度」**不是零点几度的小动作，而是一次整圈自转**（约 15 s，绕工具轴转
不改变法兰位置，所以 TCP 速度一直是 0，看起来像卡死）。所以：

- 阈值从 170° 改成 **300°**，只在快撞限位时才动手
- 大约每 5~6 条笔画才触发一次
- 真到了要绕的时候，接受这 15 s，别以为是死机

### ⑤ 归位不再是「回固定高位」

用户明确要求去掉。现在是三段接近：

```
当前姿态 → 竖直抬到 (纸面+80mm) → 平移到起点正上方 → 竖直落到起点
```

竖直段比斜线安全（不会贴着桌面横扫）。三段都要过 `_arm_gate()`，任何一段不过就根本
不开连接。**注意**：网页上「执行前回固定高位」那个勾以前默认是勾着的，会偷偷走回老
逻辑，现在已经默认关闭。

### ⑥ 一个常量没定义，能把真机停在半路

`DobotArm.current_cmd_id()` 用了 `self.CMD_ARRIVE_INDEX`，而那个常量**从来没定义过**。
离线测试用的是假臂，自己实现了同名方法，所以 125 个测试全绿也发现不了。

真机上的表现：下发到第 40 个点时抛 `AttributeError`，外层只捕 `ArmError`，异常穿透 →
整条轨迹判「未执行」，臂被 `Stop()` 硬停在半路，桌子都跟着震。

现在有两道防线：

- 测试 `test_every_cmd_constant_really_exists` 用反射扫 `DobotArm` 里所有 `self.CMD_*`，
  少一个就红
- 限流查询失败**不再中断笔画**（它只是一条状态查询），降级为不限流并记
  `dispatch.throttle = off(...)`

### ⑦ 强制结束服务进程会把控制柜的端口占住

`Stop-Process` 硬杀之后，30004/29999 会**拒绝连接或超时**十几秒到几十秒（控制柜还记着
那条死连接）。现场表现是「臂突然连不上了」，很容易误判成网线掉了。

对策：杀完**等 10~20 秒**再起服务；或者在页面上用 `/arm/attach` 重连，不用重启服务。
重启服务时先用 29999 探一下通不通，通了再起。

## 3. 还没解决的问题

### J6 漂移只是被「兜住」，没有根治

现在的做法是「快撞限位了做一次整圈复位」。根本原因是**我们下发的是位姿**：

```python
MovL(pose={x,y,z,180,0,0}, r=5)
```

控制器自己解 IK，J6 取哪一支由它决定，我们的防缠逻辑（`cable.choose`）**管不到轨迹中间
的点**——它只校验了起点那一段。

真正想解决得二选一：

- **A. 让每段自己把 J6 拉回中性**：`rz`（绕竖直轴的朝向）只影响手指朝向、不影响指尖
  位置，给每个点选一个让 J6 最接近 0 的等价 `rz`（±180 里挑）。需要验证控制器的 IK 会
  不会跟着选同一支。
- **B. 改关节空间下发**：自己算好整条关节流，用 `MovJ(joint=...)` 逐点下发。但 `MovJ`
  是关节插值，**指尖不走直线**，写字会变形——除非改成 `MovLIO`/`ServoJ` 之类。

### 书写段还有轻微掉速

`r=5 + 15 mm` 那一组已经 0 次「连续 3 帧 <2 mm/s」，但曲线上仍有 2~3 个浅坑（掉到
40~80 mm/s 再起来）。想更顺可以继续试：

- `r=7`（点距同步放宽到 20 mm，保证 r ≤ 0.45×点距）
- `accel_pct=50`（加速度比例，`a=` 参数，还没系统试过）
- `speed` 50~60%

### 纸面精度还没量过

所有测试都是看「顺不顺」，**没有量过实际笔迹和预期轨迹差多少**。`r` 会把拐角磨圆，
磨掉多少是未知数。下一步应该画一条 100 mm 直线和一个直角，用尺子量：

- 直线长度误差
- 直角处的圆角半径（应该 ≈ `blend_r_mm`）

### 灵巧手是仿真总线

服务用的是 `--bus sim`，所以 `hand_home` 只是「假装成功」，手不会真的动。写字时笔是
靠手夹住的，手姿态对不对没人验证过。真要动手指得用 `--bus can`（需要 CAN 适配器空闲）。

## 4. 下一步建议（按优先级）

1. **量纸面精度**：100 mm 直线 + 直角，量长度和圆角半径，确认 `r=5` 磨掉了多少。
   这是唯一还没有数据的一环。
2. **决定 J6 的根治方案**（第 3 节 A 或 B），现在的兜底只能算缓解。
3. 想更快更顺，再试 `r=7 / step=20` 和 `accel_pct=50` 两组，用 `trace_track.py` 对比。
4. 如果要做「预演→确认→下发」的完整闭环，网页上已经有了；缺的是预演动画的时长要和
   真实下发对齐（现在 `tip_speed_mm_s=40` 只是个估计，和实际速度因子无关）。

## 5. 怎么验证

```bash
# 不连臂的自检（单测 + 仿真 + 假臂下发顺序）
python scripts/trace_check.py

# 回归测试（131 个，约 2 分钟）
python -m unittest tests.test_trace2d tests.test_trace_apply tests.test_arm \
    tests.test_arm_actions tests.test_kin tests.test_arm_poses tests.test_arm_feed

# 只看规划，不动臂
python scripts/trace_track.py --shape corner --r 5 --step 15 --speed 40

# 真机 + 速度曲线（带仪表）
python scripts/trace_track.py --shape corner --r 5 --step 15 --speed 40 --apply --yes
```

`trace_track.py` 的输出长这样：

```
下发 25 点  实际耗时 9.0 s  规划预计 8.9 s
TCP 速度：最大 255.0  平均(运动中) 167.3  最低(运动中) 2.0 mm/s
停顿（速度掉到 <2 mm/s 连续 3 帧）：0 次
分段计时： connect=0.0s  approach=2.3s  start=3.0s  write=3.2s  close=5.3s
```

判据：

| 现象 | 含义 |
| --- | --- |
| 速度曲线是**一条连续曲线** | 顺 |
| 等幅锯齿、每段掉到 0 | 每个点都在停车（`cp` 无效或 `r` 太大/被拒） |
| `timings` 里 `close` 远大于 `write` | 时间花在收笔等待，不是运动慢 |
| `timings` 里 `approach` 很大 | 接近段太长（起点离当前位置远）或腕部归中在转整圈 |

## 6. 硬件现场备忘

- 臂：Dobot Nova 5，`192.168.5.1`，控制口 **29999**（dashboard 文本协议），反馈口
  **30004**；本机 USB 网卡地址 `192.168.5.100`
- **29999 同一时刻只允许一个客户端**；30004 对并发连接很敏感，别自己另开一条
- 30004 的 `TCPSpeedActual` 单位是 mm/s，服务里换算成 m/s 暴露成 `tcp_speed_m_s`
- 报警时 29999 只允许 `ClearError / GetErrorID / Stop / RobotMode` 等少数指令；
  读报警用 `python scripts/arm_fault.py`（`--clear` 会顺手清一次）
- 通用错误码：`-1` 命令执行失败（收到了但执行失败，多半是几何/规划问题）、
  `-2` 报警中、`-3` 急停、`-4` 下电、`-10000` 命令不存在、`-20000` 参数个数错、
  `-50001` 参数类型错（`r=3.0` 就是踩这个）
