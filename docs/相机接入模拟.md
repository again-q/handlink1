# 摄像头实时环境接入模拟：研究结论与实施方案

> 研究日期：2026-11-17。对象：`handlink`（LG-603 灵巧手 + Dobot Nova 5 + 俯视相机 +
> three.js 安全环境）。结论先给，方案对比、精度预算、限制和升级路线在后面。

---

## 0. 一句话结论

**用「桌面平面单应」把相机像素换成臂基座坐标，把相机认出的物体写进
`cell`，让 `/arm3d` 和下发闸门共用同一份世界模型。** 这条路 4 对点就能标定、
不需要内参、当天能跑通；代价是只对**桌面平面**成立，人要等第二阶段补内参 + PnP。

**不要**走「把视频当背景贴上去」那条路：看起来像接入了，但画面不参与任何
间距计算，安全闸门拿到的还是出厂模型——那只是换了个壁纸。

---

## 1. 问题拆解：「接进模拟」其实有三种

| 层次 | 做什么 | 解决的问题 | 本机状态 |
| --- | --- | --- | --- |
| **A. 看得到** | 相机画面叠到三维场景里，和模型对齐 | 人对位、演示、发现标定错了 | ✅ 已落地（桌面贴图） |
| **B. 算得准** | 相机 → 基座坐标 → 物体表 → 碰撞模型 | 安全间距、下发拦截、抓取目标 | ✅ 已落地（桌面物体） |
| **C. 闭环** | 相机读数反过来控制臂/手 | 推层补角度、视觉伺服 | ⏳ 只有魔方读数的接口 |

A 是演示，B 才是「接入模拟」的核心，C 是下一步的应用。三者共用同一个标定和
同一套坐标，所以先把 B 打穿，A 顺手就有，C 只需要接状态机。

## 2. 现状盘点

### 2.1 已经有的

| 模块 | 能力 | 对这次的作用 |
| --- | --- | --- |
| `camera.py` | MJPEG 取流、旋转/镜像、最新帧、JPEG/PNG | 提供**同一帧**给识别和贴图 |
| `cubecv.py` | 俯视读 U 面 9 格 + 层转角，中位 130 ms | 唯一现成的「物体位姿」来源 |
| `cell.py` | 工位几何、胶囊代理、`clearance()` / `check_path()` / SSM | 安全模型，**已经接受外部 cell** |
| `armview.py` | three.js 原厂 STL + 工位 + 碰撞 HUD | 三维呈现，`CELL.obstacles` 可动态加 |
| `arm_feed.py` | 30004 关节角，125 帧/秒 | 臂的姿态真值（相机不参与） |
| `service.py` | HTTP + 线程模型 | 加接口的地方 |

### 2.2 缺的那一层

```
相机像素 ──?──► 基座坐标 ──?──► 带时间戳的物体表 ──?──► cell / 三维视图
```

三处都是断的：

1. **没有像素→基座的映射**：`/vision` 只给像素坐标，`cubecv` 的 `center` 是
   `[320.4, 240.1]`，臂不知道那在哪。
2. **没有「现在的」工位**：`CELL` 是常量，魔方、杯子、料盒都不在里面。
3. **没有失败语义**：视觉丢一帧，物体该不该消失？服务停了，闸门还放不放行？

`scene.py` 就是把这三处补上。

## 3. 方案对比：四条路

| 方案 | 需要什么 | 精度 | 能覆盖 | 成本 | 主要问题 |
| --- | --- | --- | --- | --- | --- |
| **A. 桌面平面单应**（选它） | 4 对点（点桌角） | 2～4 mm/px，标定点附近 ±5～15 mm | 桌面上的物体 | **半天** | 只对 `z=0` 平面成立；镜头畸变边缘会偏 |
| B. 内参 + ArUco + PnP | 棋盘格 + 标记 + 手眼 | ±2～5 mm（全空间） | 桌面、地面、人、相机视锥 | 1～2 天 | 要标内参、要 `solvePnP`、要维护 `T_base_cam` |
| C. 深度相机（Gemini 336L） | `pyorbbecsdk`（cp310/311）+ 对齐 | ±5～20 mm（深度噪声） | 任意 3D 物体、人 | 2～3 天 | 本机 Python 3.13 没轮子；UVC 深度路不出图 |
| D. 端到端学习（检测/分割 + 6D pose） | 模型 + 数据 + GPU | 取决于训练 | 任意已知类别 | 1～2 周 | 数据、部署、不可解释；安全上最难验收 |

**为什么先选 A：** 臂的工作空间就在桌面上方 0～40 cm，所有要避开的静态物体和
魔方都在 `z≈0` 的平面上。平面单应把这一个平面做到毫米级，比 B 少掉内参、
畸变、手眼三组误差源；B 的价值在「人」和「地面」，那是第二阶段的事。

> 一个容易忽略的点：单应 **H 同时吸收了内参、外参和图像 y 轴朝下的翻转**。
> 所以不要再单独翻 v，也不要在 H 之外再乘一个旋转——这是这类代码最常见的错。

### 3.1 如果「模拟」指的是 MuJoCo / Isaac Sim

那是另一条路，但标定可以复用：

- 本方案的 `H` 只适合平面；进 MuJoCo/Isaac 需要 **K（内参）+ T_base_cam**，
  就是方案 B 的产物。拿到以后，仿真里的相机直接用同一个 `K`、同一个外参，
  渲染出来的画面和真实画面对齐（domain randomization 之外）。
- 传感器接入走 ROS 2：`sensor_msgs/Image` + `CameraInfo`，Isaac 用 OmniGraph /
  ROS 2 bridge，MuJoCo 用 `mujoco.renderer` 或外部图像张量。
- **但**：现在这套 three.js + 解析胶囊距离是「在线安全监控」，8 Hz、零依赖、
  改一行就能跑；搬去 MuJoCo 要把 TCP 反馈、MovJ、闸门全部重写，收益是动力学，
  不是安全。**先在这套里把标定和世界模型跑对，再决定要不要搬。**

## 4. 选定方案：桌面平面单应

### 4.1 数学

像素 `(u,v)` → 基座 `(x,y)`（桌面 `z=0`）：

```
[x', y', w]ᵀ = H · [u, v, 1]ᵀ ,   x = x'/w,  y = y'/w
```

四对点解 H：每对给两个方程，8 个未知数（H 差一个尺度），`SVD` 取最小奇异向量。
实现里做了 **Hartley 归一化**（平移到质心、缩放到平均距离 √2）——不做这步，
四点解会病态到没法用。点数 > 4 时是最小二乘，点得不准时更稳。

`scene.solve_homography()` 同时检查：

- 至少 4 对、数量一致；
- 任意三点不共线（共线时 H 退化）；
- 结果有限、`H[2][2]` 可归一化。

### 4.2 桌角预设与方向

`preset_world(rotate, mirror)` 用 `cell.TABLE_SIZE`（1.40×0.90 m，桌面中心 =
基座原点）生成四角。约定按**画面里**左上→右上→右下→左下点：

```
画面左上 = (-0.70, +0.45)     画面右上 = (+0.70, +0.45)
画面右下 = (+0.70, -0.45)     画面左下 = (-0.70, -0.45)
```

相机装反/装转了不用重装：`rotate` 转 90° 的整数倍、`mirror` 左右翻，8 种组合
在网页上试一遍，看 `/arm3d` 的贴图和真实桌面对上为止。**真机验收建议用
`world` 显式给点**（卷尺量四个桌角的基座坐标），别依赖「相机应该是正的」。

### 4.3 精度预算

| 误差源 | 量级 | 说明 |
| --- | --- | --- |
| 像素量化 | ±1 px ≈ ±2.8 mm | 640×480，1.4 m 桌面占 ~500 px |
| 手点角点 | ±2～5 px ≈ ±6～14 mm | 网页上放大点、点桌角的内沿 |
| 平面假设 | 0（物体底面在桌面） | 物体有高度时，顶面像素按 `z=0` 反投影会沿视线偏 `h·tanθ` |
| 高度视差 | 0～20 mm | 相机垂直向下 ≈ 0；斜视 20° 时 57 mm 魔方约 20 mm |
| 镜头畸变 | 边缘 ±5～15 mm | 没做内参/去畸变；画面中心最好 |
| 视觉中心 | ±1～3 px ≈ ±3～8 mm | `cubecv` 合成图角度误差 < 2.5° |
| **合计（标定点附近）** | **±10～20 mm** | 用于安全粗筛/可视化够；抓取对中要 B 方案 |

> 注意：`rms_mm` 是**标定点自己的残差**，不是全桌面的真实误差。四点解在
> 四个点上必然接近 0；要评估全桌面，得另取 6～8 个检查点量一遍。

### 4.4 角度约定

魔方的 `theta` 是图像里的面朝向。世界朝向不能直接拿来用：

1. 取面中心 `p0` 和 `p0 + (cos θ, sin θ)·cell_px`；
2. 两点都反投影到桌面，得到世界向量；
3. `yaw = atan2(dy, dx)`。

这样自动吸收了「图像 y 向下、世界 y 向上」的翻转。魔方的碰撞体用
**带 yaw 的盒子 → AABB**（`|w·cos|+|d·sin|`），只会更大，不会漏。

## 6. 安全语义（比精度更重要）

### 6.1 世界模型是「同一份」

`scene.cell()` 返回 `deep copy(CELL) + 物体`。服务端 `arm_move`、`/arm/check`、
`/arm/cell?live=1`、页面 HUD 用的是同一份几何。不存在「页面避开了、下发没避开」。

### 6.2 丢帧不删物体

视觉丢一帧（臂挡住、反光、转 45°）不等于物体消失：

- 视觉结果停 `VISION_STALE_S = 2 s` 就判失效；物体本身保留 `CUBE_TTL = 3 s`，
  期间仍参与间距计算，超过 TTL 才移除（判失效比 TTL 早，避免「TTL 到期到判失效」
  之间有一段桌子看起来是空的）；
- 标定过但相机没跑、或视觉失效时，`apply=true` **拒绝下发**，要 `force=true` 才放行。

这是「宁可多拦一次」的失败安全（fail-safe），不是失效安全（fail-operational）。

### 6.3 视觉不能当安全等级设备

这是必须写清楚的：

- 相机是普通 UVC，不是安全相机；没有 PL d、没有双通道、没有自检；
- 1 Hz 的视觉刷新 + 130 ms 识别，端到端 **0.2～1.2 s**；
- 所以它只适合**减速/提醒/下发前粗筛**，不能替代安全激光雷达、光幕或急停。

按 ISO/TS 15066 的 SSM 简化式 `S = v·t + v²/(2a) + C`，如果拿视觉做保护，
`t` 必须把相机曝光 + 传输 + 识别 + 场景刷新全加进去（本机约 0.3～1.2 s），
不能沿用 `cell.ssm_required()` 里 0.20 s 的工程假设值。

### 6.4 保守近似

- 物体碰撞体是 AABB（带 yaw 外扩）或圆柱，只会比实物大；
- 机械臂碰撞代理是 STL 切片胶囊，外扩 2%；
- 人的位置还是写死的 8 段胶囊——**没接**（§7）。

## 7. 不能做什么（已知限制）

1. **平面外的东西不行**：站着的人、地面、桌下的东西。像素按 `z=0` 反投影，
   人会落到错误的桌面上。要人，先做内参 + 外参（§8 阶段 2）。
2. **镜头畸变**：没做去畸变，画面边缘的映射会偏；标定和物体都要尽量靠画面中心。
3. **斜视有高度视差**：`cubecv` 给的是**顶面**中心，按 `z=0` 反投影会沿视线偏
   `h·tanθ`（57 mm 魔方在 20° 斜视下约 20 mm）。相机尽量垂直向下；手动放物体时
   点**与桌面接触的位置**，不要点顶面。
4. **只认魔方**：`cubecv` 是魔方专用。杯子/料盒/工具要 `POST /scene/place`
   手点一下，或者等检测模型（§8 阶段 3）。
5. **单相机遮挡**：机械臂挡住魔方时，视觉给不出新读数，只能靠 TTL 顶 3 s。
6. **相机不能动**：动了要重新标定——这是 eye-to-hand 的前提。
7. **标定质量取决于点得准**：网页点桌角有 ±2～5 px 的手误差；卷尺量角点 +
   `world` 显式给点更稳。
8. **改分辨率 / 旋转 / 镜像后必须重标**：H 是按当时那一帧的像素算的，换了
   `CameraConfig` 的 `width/height/rotate/mirror`，像素坐标就变了。
9. **不是安全认证**：见 §6.3。真机验收要按现场风险评估重标阈值和 SSM 参数。

## 8. 升级路线（按性价比）

**阶段 2：内参 + 外参（1～2 天）**
- `cv2.calibrateCamera` 拍棋盘格（10～20 张）→ `K`、`dist`；
- 桌面贴一张 ArUco（`docs/aruco-7.png` 现成），`solvePnP` 得 `T_base_cam`；
- 收益：去畸变、相机视锥可视化、地面平面（人）、任意 3D 点；
- 注意：`T_base_cam` 是 eye-to-hand 的固定外参，标一次存 `config/`。

**阶段 3：任意物体（2～3 天）**
- 检测：YOLO/RT-DETR 出类别 + 框；单目用「框底边中点 + 桌面平面」估 3D 位置；
- 有深度就上 Gemini 336L（`pyorbbecsdk` 要 cp310/311，本机 3.13 得换解释器）；
- 分割（SAM 类）可把「手点一下」变成「点一下自动分割出轮廓」。

**阶段 4：闭环（W3～W4 的推层）**
- 每推一次 → `POST /scene/detect` → 角度不到 85° 补推、超过 95° 回推；
- 这条已经在《魔方单手方案》§7.5 里，缺的就是「把读数接进状态机」；
- 视觉延迟 1 Hz 对推层够（推一次 2 s），对抓取对中不够。

**阶段 5：换仿真器（可选）**
- 同一套 `K` + `T_base_cam` 直接给 MuJoCo/Isaac 的相机；
- ROS 2 `sensor_msgs/Image` + `CameraInfo` 是通用接口；
- 但只有要做动力学/规划研究时才值得，安全监控继续留在这套里。

## 9. 真机操作清单（相机装好后 10 分钟）

1. **固定相机**：托盘正上方，镜头垂直向下，画面里桌面四角都看得见；
   装好以后不要再碰。
2. **打开相机**：`/vision` 页面点「打开相机」（或用 `dshow`，本机 MSMF 有时 0 fps）。
3. **点桌角**：点「点桌面四角」→ 画面左上→右上→右下→左下。残差 > 30 mm 就重点。
4. **核对方向**：打开 `/arm3d`，勾选「在桌面叠加相机画面」。如果贴图转了 90°
   或镜像了，回 `/vision` 换「方向 / 镜像」再点一次。
5. **放魔方**：托盘里放魔方，看 `/arm3d` 的橙色方块是否压在魔方上；
   不压就看残差和 `mm/px`，重点角点。
6. **看安全间距**：拖关节滑块或 `POST /arm/check`，确认物体进了 `pair`。
7. **记录**：标定残差、`mm/px`、视觉延迟，填到本页表格（下次回归对比）。
